# Point labels as entities rather than operation cues

Cycle 66 retained two compiled 2D dispatch failures for a point named `slope`: a distance request applied slope analysis or asked its clarification. A separate TensorFlow head probe had 16/16 intents, 15/16 raw endpoint mappings but only 9/16 complete endpoint pairs above confidence gates. The two probes measure different layers and remain retained with their model/source hashes.

New regression tests reproduced three failures before the change: dispatch, intent normalization and token-feature invariance (`lexical-point-before-fix.log`). A related-operation test then reproduced a slope request being redirected by a point named midpoint (`lexical-point-related-operations-before-fix.log`).

Recognized endpoint spans are now masked by position, preserving operation words and original token values/offsets. This covers distance grammar and compatible explicit `between ... and ...` references. The same preprocessing is used by training and Android inference. Explicit point-distance requests resolve before broad 2D geometry cues; compatible pair-operation dispatch uses masked cues but executes against the original named scene references. No point-name vocabulary was added to model training, and scene coordinates remain deterministic engine inputs.

A further regression proved that an actual point named origin was ignored in favor of the virtual coordinate origin (`lexical-origin-before-fix.log`: expected distance 5, received sqrt(52)). Scene references now resolve actual uniquely named points first; virtual origin remains available when no actual point bears that name. Actual origin-named points also appear in existing-point choices.

Six JVM methods cover all 150 original distance utterances with 17 lexical/Unicode/control labels in both geometry studios (5100 cases), feature/intent invariance, ordinary slope/midpoint preservation, actual/virtual origin and saved existing-point choices. These and the related point, slope, circle, triangle and recovery suites passed.
